NXdesk

A Frappe-based ecosystem of company applications

  • In development

NXdesk began as a plan to adapt Frappe Helpdesk for internal use. I proposed turning it into a wider set of connected applications behind one entry page, with access control at the application level.

Project summary

From one Helpdesk to an application ecosystem

Where it started
The company wanted to take the existing Frappe Helpdesk repository and adapt it for internal use, with fairly small customizations.
What I proposed
Treat Helpdesk as the first of several applications instead of a one-off customization: one entry page and sign-in, shared platform services, clear boundaries between applications, and access that follows each person’s role.
My contribution
The ecosystem proposal, plus analysis and design work on Frappe’s multi-app, single-site setup, roles and permissions, and how people should be routed after they sign in.
Technology
Frappe Framework, ERPNext and Frappe Helpdesk (Python, Vue).
Current status
A team product in development. The entry page below is an early draft, and the multi-application architecture is a proposal, not a finished system.

My work areas

What I worked on in the Frappe platform

  • Frappe Framework and Frappe Helpdesk integration.
  • Multi-app, single-site architecture.

Architecture proposal

The proposed six-application ecosystem

Proposal only

The ideas below are system designs I explored and proposed. None of them is built or running in production.

One entry page, many applications

A single place to sign in, showing only the applications a person is allowed to use.

Database per application

Each application owns its data, with a shared database only for information that really is common.

API-based integration

Applications read each other’s data through APIs instead of reaching into each other’s tables.

Event-driven synchronization

Changes are published as events so other applications can keep a copy up to date.

Shared read models (CQRS)

Read-optimized views that combine data from several applications for dashboards and search.

Hybrid approach

A mix of the options above, chosen per application, based on how much data must be shared.
